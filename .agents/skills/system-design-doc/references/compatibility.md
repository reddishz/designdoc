# 子系统接口兼容性

## 适用范围

本页约束**子系统之间**以及**子系统对系统外部**的公开契约：`IF` 接口、`ACT` 动作、事件、数据契约。子系统内部实现细节不受此限。

接口的权威定义属于**提供方**子系统；消费方通过完整编码引用，并在自己的基线 `depends_on` 中钉住提供方版本。

## 变更分级

| 级别 | 版本位 | 典型变更 | 是否可用 PATCH |
|------|--------|----------|----------------|
| 兼容修复 | PATCH（`full_version` Z） | 文档澄清、缺陷修复、性能优化；公开语义与形态不变 | 是 |
| 兼容新增 | MINOR | 新可选字段、新操作、新事件、宽松化校验 | 否（走 MINOR） |
| 破坏性变更 | MAJOR | 删除 / 重命名、类型变更、语义变更、新增必填、默认值改变导致行为变化 | 否 |

**PATCH MUST NOT 改变公开接口语义**。只要消费方需要改代码或改配置才能继续正确工作，就不是 PATCH。

## PATCH 与验证结论

PATCH 的兼容性来自「公开语义与形态不变」，不是因为版本号变化小。允许沿用既有兼容结论的前提是提供方确认本轮未改变公开契约；只要涉及字段、行为、默认值或必填性变化，就按 MINOR / MAJOR 处理。消费方可按自身风险决定是否复验；系统发布若要声称已验证，应在发布说明中指向覆盖该组合的 EVAL / L6 证据。

## 提供方义务

1. **先设计后实现**：接口变更先改提供方 `IF` / `ACT` 定义与验证，再改代码（design-doc 的 `before-code-change`）。
2. **MAJOR 先通知**：在发布前识别受影响消费者；所有消费者更新 `depends_on` 并重验后，才可进入系统发布。
3. **弃用通道**：删除公开接口前，**SHOULD** 至少保留一个 MINOR 周期，标注 `废弃` 与替代方案；系统发布说明记录。
4. **不静默改变语义**：同一编码下改变含义属于破坏性变更，**MUST** 走 MAJOR 或新编码 + 作废旧编码，**MUST NOT** 借维护性变更掩盖。
5. **验证证据**：L6 追溯矩阵与 EVAL 证据应覆盖新版本接口；EVAL 的 `对照版本` 指向已冻结基线。

## 消费方义务

1. 消费方基线 **MUST** 钉住提供方精确 `vX.Y`；`full_version` 不作为依赖单位。
2. 提供方发 MINOR 后，消费方**不自动升级**；要采用新 MINOR，须重验、立新基线、改钉住。
3. 提供方发 MAJOR 后，消费方 **MUST** 在下一个系统发布前完成适配或明确退出该组合。
4. 跨子系统引用 **MUST** 写全量编码；简写仅限子系统内部引用。
5. 消费方 **MUST NOT** 通过复制提供方文档来「固定」契约；契约仍以提供方编码为准。

## 系统发布前的兼容性检查

1. 清单内每个子系统的 `depends_on` 目标都在发布清单中，版本完全一致。
2. 清单内每个子系统的 `external_deps` 在发布清单中有同名同版本项；无冲突。
3. 发布清单中的 `full_version` 都在对应基线 `patch_log` 中。
4. 若本轮包含 MAJOR 变更：确认所有消费者已更新基线；发布说明列出不兼容点。
5. 若本轮包含 MINOR：确认没有消费者仍在旧钉住上却被强制升级；发布清单如实记录组合。

## 与部署无关

接口兼容性是**设计契约**问题，不是部署拓扑问题。本技能只校验版本钉住与接口契约，不校验部署形态。
