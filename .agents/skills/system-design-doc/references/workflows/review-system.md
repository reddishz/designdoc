# 系统结构与发布审查

先跑检查器，再按本清单人审。检查器通过不代表角色划分、边界与接口语义正确。

```bash
python3 .agents/skills/system-design-doc/scripts/check_system.py -p ued
python3 .agents/skills/system-design-doc/scripts/check_system.py -p ued --print-member-commands
```

## 结构

- [ ] `ued/README.md` 有「当前结构」说明，明确这是系统 + 子系统。
- [ ] 系统根**没有** `产品版本`、`baselines/`、`文档索引`、`编码计数器`、`全局编码索引`。
- [ ] 系统根没有 `L0-vision/`–`L6-verification/` 设计作用域。
- [ ] 每个子系统目录都是 `ued/` 直接子目录，没有嵌套子系统。
- [ ] 没有未登记的目录（`references/`、`assets/`、`releases/`、`deprecated/` 除外）。
- [ ] 没有固定 `shared/` 特殊概念；共享库只是普通子系统。

## 注册表

- [ ] 六列齐备：`subsystem_key` / 子系统名称 / 目录 / 编码前缀 / 角色文档 / 状态。
- [ ] 键、目录、前缀各自唯一；键未复用。
- [ ] 每个目录存在且含 `README.md`。
- [ ] 前缀与子系统 README 的 `project_code` 一致（都空或都同值）。
- [ ] 状态只取 `初稿` / `正式` / `废弃`，无 `草案`。
- [ ] `正式` 子系统均有角色文档、`产品版本`、对应基线。
- [ ] `废弃` 子系统目录与文档仍保留，且不出现在新发布中。

## 角色与边界

- [ ] 每个 `正式` 子系统的 `CMP` 角色文档为 `正式`。
- [ ] `CMP` 覆盖角色、范围边界、交互对象与动作。
- [ ] 子系统职责无重叠；边界与非目标写清。
- [ ] 系统级内容放在承担职责的普通子系统或根 README 摘要中，没有另建特殊根作用域。
- [ ] 跨子系统交互契约定义在提供方子系统中，消费方用完整编码引用。

## 依赖

- [ ] 每个 `正式` 基线有 `depends_on` / `external_deps`（无依赖写 `[]`）。
- [ ] 依赖目标已登记且 `正式`。
- [ ] 目标 `vX.Y` 基线存在。
- [ ] 无自依赖、无重复、无外部名冲突。
- [ ] 依赖变化通过新基线表达，不是 PATCH。
- [ ] 环依赖已评估；不应存在的已消除。

## 系统发布

- [ ] 发布清单包含当时全部 `正式` 子系统，且不含 `初稿`。
- [ ] `product_version` 与 `full_version` 一致，后者在 `patch_log` 中。
- [ ] `depends_on` 目标在清单中且版本一致。
- [ ] `external_deps` 全覆盖且无冲突。
- [ ] 文件名、`release` 字段、README 发布索引一致。
- [ ] 历史发布清单未被修改。
- [ ] MAJOR 接口变更的消费者均已适配并更新钉住。

## 编码与术语

- [ ] 子系统定义使用自己的前缀；跨子系统引用写全量编码。
- [ ] 同一完整编码只在一个子系统中定义。
- [ ] `ued/glossary.md` 全系统唯一；子系统没有自己的 glossary。
- [ ] 术语 `定义位置` 指向的文档存在且唯一。
- [ ] 每个子系统 design-doc 检查通过（使用 `--glossary`）。

## 常见驳回

- 系统根放了产品版本或 L2 文档。
- 共享库被建成特殊 `shared/` 作用域。
- 子系统依赖只写 README 口头说明，基线没有 `depends_on`。
- 用 PATCH 改了依赖钉住。
- 系统发布漏掉某个 `正式` 子系统，或版本与依赖不一致。
- 发布后直接改清单。
