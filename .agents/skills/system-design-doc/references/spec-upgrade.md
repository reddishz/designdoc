# 系统层规范版本与规范迁移

本技能（system-design-doc）升级后，已有的系统层文档需要跟随迁移。本文界定系统层「哪些已对齐、哪些待迁移」，以及每次升级对各类系统层对象的要求。子系统内部文档不在此列：它们是独立的 design-doc 作用域，见 [design-doc · spec-upgrade](../../design-doc/references/spec-upgrade.md)。

## 记录位置

| 对象 | 记录 | 含义 | 何时更新 |
|------|------|------|----------|
| 系统根 `ued/README.md` | `规范版本目标` | 本系统层要求对齐到的 system-design-doc 版本（裸数字，如 `2.1`） | 升级技能后确认影响表，再改目标（声明要求，不代表已完成） |
| `architecture/system-architecture.md` | 封面 `规范版本` | 本篇已迁移或核对到的版本 | 仅在该篇迁移或核对后更新 |
| 每篇 `architecture/SYS-ADR-*.md` | 封面 `规范版本` | 同上 | 同上 |
| `releases/sys-vX.Y.yaml` | 不逐篇记录 | 发布清单是结构化发布快照，不是普通设计文档 | 仅当某次升级改变其格式或必填字段时，在影响表中声明处理方式 |
| 根 README 的子系统注册表 | 不逐篇记录 | 随根 README 的 `规范版本目标` 一并对齐 | — |

取值与 `SKILL.md` 的 `metadata.version` 同形。它**不是**文档 `修订版本号`，也**不是** `architecture_rev`。

**为什么 `architecture_rev` 不能代替逐篇记录**：`architecture_rev` 追溯的是系统架构**内容**的修订代际。只调整格式、结构且不改变架构含义的规范迁移，不会改变它。因此它不能证明某篇文档已完成迁移，迁移进度只能由逐篇 `规范版本` 表达。

## 判定规则

1. **目标与已装不一致**：根 README `规范版本目标` ≠ 已装版本 → WARNING。
2. **逐篇待迁移**：文档 `规范版本` 低于根目标 → WARNING，列出该篇。检查器不据版本号大小判定是否需要改内容，以[迁移性质](#迁移性质判定)与影响表为准。
3. **文档超前**：文档 `规范版本` 高于已装版本 → ERROR（技能回退或版本不一致）。
4. **缺失**：系统架构或 `SYS-ADR` 缺 `规范版本` → WARNING（存量允许，不阻断）。新建文档由模板带入。
5. **根目标缺失**：WARNING，且不判待迁移。
6. **迁移元信息不计修订**：只更新 `规范版本` 或 `规范版本目标` 时，不递增 `修订版本号`、不追加修订记录、不改 `architecture_rev`。
7. **历史发布清单只读**：已发布的 `sys-vX.Y.yaml` 不因规范升级而改写。

数值比较：`2.10` 高于 `2.9`，不按字符串比较。

## 迁移性质判定

系统层沿用 design-doc 的[迁移性质判定](../../design-doc/references/spec-upgrade.md#迁移性质判定)：判据是**系统架构的语义是否改变**，而不是规范是否新增了要求。

| 迁移情况 | 处理方式 |
|----------|----------|
| 纯格式、结构调整（章节顺序、表格、模板替换、迁移到新章节结构） | 维护：**不递增** `修订版本号`、不改 `architecture_rev`（与[修订规则](architecture-description.md#修订记录与-architecture_rev-追溯)中「纯文字润色、排版或链接修复可不递增」一致） |
| 补充已确定但未记录的内容（须能指出既有依据：既有正式文字、已批准的 `SYS-ADR`、现行实现） | 维护：同上 |
| 改变系统定义、子系统职责分配、系统交互、系统级约束，或改变当前有效架构的 `SYS-ADR` 落地 | 实质变更：按修订规则递增 `修订版本号`、追加修订记录，必要时新发布绑定新的 `architecture_rev` |
| 无法确认是否改变系统语义 | 实质变更 |

规范迁移 MUST NOT 与实质变更放在同一改动中（隔离原则）；人审批准后执行。

## 升级影响表

每个规范版本在本节登记影响表，说明该次升级对各类系统层对象分别有什么要求。

| 列 | 含义 |
|----|------|
| 规范版本 | 引入变更的版本 |
| 变更项 | 规则层面的变化（一条一行） |
| 影响对象 | 系统架构 / `SYS-ADR` / 发布清单 / 注册表 / 根 README |
| 动作 | `需迁移` / `仅新建` / `不处理存量` / `核对即可` |
| 性质 | `维护`：格式、结构或补记；`可能实质`：可能改变系统语义，须逐篇按上表判定 |

|----------|--------|----------|------|------|
| 2.1 | 根 README 新增 `规范版本目标` | 系统根 README | 仅新建：模板已带入；存量：`核对即可`（缺失仅 WARNING） | 维护（仅迁移元信息） |
| 2.1 | `system-architecture.md` 与 `SYS-ADR` 封面新增 `规范版本` | 系统架构、`SYS-ADR` | 仅新建：模板已带入；存量：`核对即可`（缺失仅 WARNING，核对后补填） | 维护（仅迁移元信息，不写修订记录） |

## 操作步骤

1. 升级技能后运行 `check_system.py`，查看「系统 README 规范版本目标与已装不一致」。
2. 阅读本文件版本记录，确认各行动作与性质。
3. 把根 README 的 `规范版本目标` 改为新版本。
4. 逐篇处理「系统文档待迁移规范」清单：需改内容的按迁移性质分流，核对无需改动的仅更新 `规范版本`。
5. 清单清空、目标与已装一致后，本次升级结束。
