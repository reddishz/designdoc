# 系统与子系统模型

## 三视角模型

由多个子系统组成的软件系统包含三个相互关联、但**不能互相替代**的设计视角：

| 视角 | 核心问题 | 权威归属 | 承载位置 |
|------|----------|----------|----------|
| **系统架构** | 整个系统如何组成、职责如何分配、边界在哪、如何协作、遵守哪些全局约束 | **系统层**（本技能） | `ued/architecture/system-architecture.md` 与 `SYS-ADR-*.md` |
| **子系统架构** | 单个子系统如何落实被分配的职责、内部如何划分组件与契约 | **子系统**（`design-doc`） | `ued/{子系统}/`（L0–L6、`baselines/`） |
| **系统组合** | 哪一组子系统版本与外部依赖构成可复现的实际交付组合 | **系统层**（本技能） | `ued/README.md` 注册表 + 子系统基线依赖 + `ued/releases/sys-vX.Y.yaml` |

## 六项权威归属

本规范的核心目标是确立以下六件事的唯一权威归属，避免多处重复定义导致漂移：

1. **系统决定子系统的职责分配**：子系统的角色、核心职责、明确非职责与边界由系统层 `ued/architecture/system-architecture.md` 权威定义；子系统不得自行改写。
2. **子系统落实被分配的职责**：每个子系统是完整的 `design-doc` 作用域，拥有独立 `产品版本`、`baselines/`、编码计数器与索引；子系统内部 `CMP` 仅表达**本子系统内部的逻辑组件**，不再充当子系统角色卡片。
3. **系统交互描述协作关系**：跨子系统的数据流、事件流、控制流与双向协作关系在 `system-architecture.md` 中表达；它不同于单向版本依赖 `depends_on`。
4. **提供方负责接口契约**：跨子系统公开接口（`IF` / `ACT` / 事件与数据契约）的字段与行为定义留在提供方子系统的 L4 文档中；系统层与消费方只引用全量编码，不复制字段。
5. **系统发布锁定具体组合**：`ued/releases/sys-vX.Y.yaml` 钉住纳入本次组合的子系统精确版本与外部依赖版本，不可变，不是设计基线，也不要求覆盖全部 `正式` 成员。
6. **系统架构修订绑定组合依据**：每个系统发布通过 `architecture_rev` 指向当时生效的系统架构正式修订号，使组合锁可追溯到当时的系统设计依据。

## 职责切分

| 事项 | 系统级 | 子系统级 |
|------|--------|----------|
| 组成 | 注册表（5 列）：键、名称、目录、前缀、状态 | — |
| 角色与边界 | `architecture/system-architecture.md` 职责分配表（唯一真源） | 承接分配职责，在 L2 / L3 落为自身需求与内部架构；`CMP` 只写内部组件 |
| 交互与契约 | `system-architecture.md` 表达协作拓扑与契约归属 | 提供方 L4 用 `IF` / `ACT` 定义接口契约，消费方用全量编码引用 |
| 全局约束与决策 | `SYS-CON`（跨子系统约束）、`SYS-ADR`（跨子系统架构决策） | L2/L3/L5 细化落实并在 `来源` 回指 `SYS-CON`；内部取舍用子系统 L3 `ADR` |
| 依赖与版本 | 发布清单钉住组合版本、外部依赖与 `architecture_rev` | 自有 `产品版本`、`baselines/`，基线写 `depends_on` / `external_deps` |
| 验证 | 架构一致性、依赖闭合、跨子系统集成验证口径 | L6 需求验证、EVAL 基线评估 |
| 术语 | 全局唯一 `ued/glossary.md` | 在文档「术语和概念」中定义本文术语并登记至全局表 |

## 共享库

共享库**不是**特殊对象：

- 它就是一个普通子系统，在系统架构文档中明确其职责边界，按相同规则登记、发版、声明依赖。
- 可以有零个、一个或多个；是否抽取共享库由系统架构决定。
- **MUST NOT** 为共享库保留固定目录（如 `shared/`）、特殊状态、特殊模板或特殊发布条目。

系统内多个子系统依赖同一个共享库时，各自在 `depends_on` 中钉住其精确 `vX.Y`；系统发布统一校验闭合。

## 系统根允许与禁止

**系统根允许**：
- `ued/README.md`（入口、当前结构、5 列子系统注册表、系统架构入口、系统发布索引、术语表链接）
- `ued/glossary.md`（全系统唯一术语表）
- `ued/architecture/`（`system-architecture.md` 与 `SYS-ADR-*.md`）
- `ued/releases/`（`sys-vX.Y.yaml` 组合锁）
- `ued/references/`（原始外部资料）、`ued/assets/`、`ued/deprecated/`

**系统根禁止**：
- **MUST NOT** 变成第二个 `design-doc` 作用域；
- **MUST NOT** 出现 `L0-vision/`–`L6-verification/`、`产品版本`、`baselines/`、`文档索引`、`编码计数器`、`全局编码索引`；
- **MUST NOT** 在 `README.md` 重复维护第二份子系统角色/职责正文（唯一真源在 `architecture/system-architecture.md`）。

## 边界与编码规则

- 子系统目录 **MUST** 是 `ued/` 的直接子目录，**MUST NOT** 嵌套子系统。
- 一个子系统 **MUST NOT** 把另一个子系统的文档纳入自己的作用域；跨子系统只引用全量编码与相对链接。
- `SYS` 为系统层保留前缀，任何子系统 **MUST NOT** 注册 `SYS` 前缀或定义 `SYS-*` 编码。
- 同一完整编码 **MUST** 只在一个子系统中定义；子系统启用编码前缀时，定义 **MUST** 使用含该前缀的全量编码。
- 子系统内部引用 **MAY** 省略本子系统前缀（如 `IF-001`）；跨子系统引用与系统级文档 **MUST** 写全量编码。
- 子系统 `废弃` 后目录与文档保留，**MUST NOT** 删除；历史发布清单与历史架构修订继续有效。

## 单系统

`ued/README.md` 没有子系统注册表时，`ued/` 就是一个 `design-doc` 单系统作用域；本技能不适用。单系统拆分或旧结构迁移见 [migration-from-design-doc.md](migration-from-design-doc.md)。
