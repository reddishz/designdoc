# 系统与子系统模型

## 定义

**系统**是顶层 `ued/`，其 `README.md` 含**子系统注册表**。系统回答「由哪些子系统组成、各自负责什么、边界在哪、如何交互、以哪组版本一起发布」。

**子系统**是 `ued/{目录}/` 下的一个完整 design-doc 作用域。子系统回答「自身如何满足需求、如何组织、如何实现与验证」，拥有独立的 `产品版本`、`baselines/`、编码计数器与全局编码索引。

**系统发布**是 `ued/releases/sys-vX.Y.yaml`，记录某一时点纳入本次组合的子系统及外部依赖的精确版本。它不是设计基线，不含细项，也不参与 design-doc 的 PATCH / MINOR / MAJOR；发布是可选动作，不要求覆盖全部 `正式` 成员。

## 职责切分

| 事项 | 系统级 | 子系统级 |
|------|--------|----------|
| 组成 | 注册表：键、名称、目录、前缀、角色文档、状态 | — |
| 角色 | 通过注册表 `角色文档` 指向该子系统的 `CMP` 细项 | `CMP` 定义自身角色、范围边界、交互对象与动作 |
| 边界 | 约束子系统之间不重叠、不越界 | 在 L2 / L3 写清范围与非目标 |
| 交互 | 汇总跨子系统依赖与发布钉住 | 用 `IF` / `ACT` 等完整编码定义契约与动作 |
| 版本 | 系统发布清单钉住纳入项的 `vX.Y` + tip | 自有 `产品版本` 与 `baselines/` |
| 外部依赖 | 发布清单统一钉住外部依赖版本 | 基线 `external_deps` 声明自身需要的外部依赖 |
| 验证 | 发布组合的依赖闭合与兼容性 | L6 验证、EVAL 证据 |
| 术语 | 全局唯一 `ued/glossary.md` | 在文档「术语和概念」中定义本文术语 |

## 角色、边界与交互

每个 `正式` 子系统 **MUST** 在注册表 `角色文档` 列指向一个 `CMP` 细项。该细项 **MUST** 覆盖：

1. **角色**：该子系统在系统中承担什么职责。
2. **范围边界**：负责什么、不负责什么；与其他子系统的边界。
3. **交互**：与哪些子系统交互、通过哪些接口 / 动作、谁提供谁消费。

`CMP` 细项位于该子系统自己的 L3 架构文档中，使用完整编码（启用前缀时带前缀）。注册表只引用编码，不复制定义。

跨子系统交互的权威定义留在**拥有该契约的子系统**文档内（通常是提供方的 L4 `IF` / `ACT`）。系统根 README **SHOULD** 维护一张交互摘要表，便于导航，但摘要 **MUST NOT** 取代子系统内的定义。

## 共享库

共享库**不是**特殊对象：

- 它就是一个普通子系统，按相同规则登记、定义角色、发版、声明依赖。
- 可以有零个、一个或多个；是否抽取共享库由系统自行划分。
- **MUST NOT** 为共享库保留固定目录（如 `shared/`）、特殊状态、特殊模板或特殊发布条目。

系统内多个子系统引用同一个共享库时，各自在 `depends_on` 中钉住其版本；系统发布统一校验闭合。

## 系统级设计内容放哪

系统级内容**不需要**单独建一个根级设计作用域。按职责选择：

- 有明确的承担者（如平台子系统、架构子系统）→ 放进该普通子系统的 L0–L6 文档。
- 只是导航或组合摘要 → 写在系统根 `README.md` 的表格或短节。
- 跨子系统的接口契约 → 放进提供方子系统的 L4 文档，消费方用全量编码引用。

系统根 **MUST NOT** 出现 `L0-vision/`–`L6-verification/`、`baselines/`、编码计数器或全局编码索引；这些属于子系统。

## 边界规则

- 子系统目录**MUST**是 `ued/` 的直接子目录，**MUST NOT** 嵌套子系统。
- 一个子系统 **MUST NOT** 把另一个子系统的文档纳入自己的作用域；跨子系统只引用编码与相对链接。
- 同一完整编码 **MUST** 只在一个子系统中定义；子系统启用编码前缀时，定义 **MUST** 使用含该前缀的全量编码。
- 子系统内部引用 **MAY** 省略本子系统前缀（如 `IF-001`）；跨子系统引用与系统级文档 **MUST** 写全量编码。
- 系统根 `references/` 只放原始外部资料；需要 `REF` 细项时放进某个子系统。
- 子系统 `废弃` 后目录与文档保留，**MUST NOT** 删除；历史发布清单继续有效。

## 单系统

没有子系统注册表时，`ued/` 就是一个 design-doc 作用域；本技能不适用。单系统迁移为多子系统时，见 [migration-from-design-doc.md](migration-from-design-doc.md)。
