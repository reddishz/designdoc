# 对象模型

`ued/` 里有哪些对象、字段由谁写入、四态下允许哪些动作。状态机与版本号见 [status-definitions.md](status-definitions.md)；编码形态与类型码见 [coding-system.md](coding-system.md)；作废步骤见 [item-deprecation.md](item-deprecation.md) / [doc-deprecation.md](doc-deprecation.md)。

| 轴 | 取值 | 回答的问题 |
|----|------|------------|
| **对象** | 文档 / 细项 / ADR / REF 文档 / 规划总览 / 注册表行 / 追溯矩阵行 | 这是什么东西 |
| **字段** | 身份 / 状态 / 内容 / 流转伴随 / 记录型 | 谁在哪一次动作里写它 |
| **状态** | `初稿` / `正式` / `草案` / `废弃` | 生命周期在哪 |
| **动作** | 创建、改标题、解冻、定稿、作废、回退、落实 | 允许做什么 |

锁定（ID / 标题 / 含义）是身份与内容字段在四态下的权限切片；定义块段位（治理 / 内容 / 追溯）是内容类字段在细项定义块里的排序。编码一经分配即占用，见下文存在性行。

## 对象种类

| 对象 | 编码形态 | 状态字段 | 定义所在 | 说明 |
|------|----------|----------|----------|------|
| L0–L6 文档 | `L{层级}-{三位序号}` | 元信息表 `状态` | 一份 `.md` | 层级文档 |
| 编码细项 | `{类型码}-{三位序号}` | `细项状态`（清单列 + 定义块治理段首行，两处 MUST 一致） | 所属文档内的定义块 | 可引用的设计对象 |
| ADR | `ADR-{三位序号}`（不含层级） | 元信息表 `状态` | `L3-architecture/` 独立文件 | 宏观架构决策档案；量级与 DEC 的分界见 [type-profiles.md · ADR 与 DEC](type-profiles.md#adr-与-dec-的定位) |
| REF 文档 | `REF-{三位序号}` | 元信息表 `状态` | `ued/references/` | 外部资料档案；内含 REF 细项时细项仍用 `细项状态` |
| 产品规划总览 | 所属层级的文档编码（默认 L1） | 元信息表 `状态` | 独立文件，只登记不定义 PLN | PLN 定义块在所属层级文档 |
| 应用注册表行 | 无细项编码 | 列 `状态`（取四态，记录型） | 多应用顶层 `ued/README.md` 的表格行 | 应用是否在用；**不是**可引用的设计细项，不进全局编码索引 |
| L6 追溯矩阵行 | 无独立编码 | 列 `追溯状态`（记录型：未追溯/已追溯/不适用） | L6 文档内表格行 | 覆盖关系；**不是**测试执行结果，不进全局编码索引 |

- 文档状态与其内细项的 `细项状态` **各自取值**；门控见 [status-definitions.md · 层级门控](status-definitions.md#层级门控文档状态--细项状态mandatory)。
- ADR / REF 的层级不写进编码，由存放目录 + 元信息 `层级` + `关联文档` 共同表达。
- 规范条文（本技能包）**不纳入**细项编码体系。指向条款 MUST 用 `文件#标题锚点`。

## 字段（按写入者）

一个字段能否随手改，取决于**谁在哪一次动作里写它**，不取决于它像不像正文。

| 类 | 谁写 | 何时写 | 成员 |
|----|------|--------|------|
| **身份** | 分配流程 | 创建时一次 | 编码 ID、类型码、文档编码；细项**存在性**（条目是否保留） |
| **状态** | 受控状态变更 | 定稿 / 解冻 / 作废 / 回退（须按权限） | 文档 `状态`；细项 `细项状态` |
| **内容** | 人 | `初稿`/`草案` 可直接改；`正式` 须先解冻 | 标题、正文段、内容段自有属性、追溯段 `出处`/`来源`、图示 |
| **流转伴随** | 状态机 | 仅创建或 `正式→草案` 解冻那一刻 | 文档 `版本`、`创建日期`；细项 `修订版本号`、`最后修订日期` |
| **记录型** | 人 | 任意状态可追加，不解冻、不变号 | 见下表 |

流转伴随与记录型的初值、回退分叉与日期语义见 [status-definitions.md · 流转伴随字段](status-definitions.md#流转伴随字段只随指定转换写入) 与 [记录型字段](status-definitions.md#记录型字段不参与冻结)。记录型成员：

| 字段 | 所属对象 |
|------|----------|
| `变更记录` | 全部对象 |
| `最后更新` | 文档 |
| `废弃时间` / `废弃原因` / `替代方案` | 已废弃对象 |
| `落实情况` / `落实记录` / `建议复审日期` | PLN 细项 |
| `来源版本` / `获取日期` / `最近核验日期` / `复查周期` / `失效风险` | REF |
| `追溯状态` | L6 追溯矩阵 |
| `状态`（注册表列） | 应用注册表行 |

`创建日期` / `修订版本号` / `最后修订日期` **不是**记录型。

### 定义块段位（属性行组内的顺序）

细项内容类与状态类字段在定义块属性行组内的顺序固定：治理段 →（废弃时）废弃登记段 → 内容段 → 追溯段。形态见 [coding-system.md · 细项定义块形态](coding-system.md#细项定义块形态mandatory)。

| 段 | 属性名 | 写入者类 |
|----|--------|----------|
| 治理段 | `细项状态` | 状态 |
| 治理段 | `修订版本号` / `最后修订日期` | 流转伴随 |
| 废弃登记段 | `废弃时间` / `废弃原因` / `替代方案` | 记录型 |
| 内容段 | 本类型码自有属性 | 内容；其中 PLN 的 `落实情况` / `落实记录` / `建议复审日期`、REF 时效字段为记录型 |
| 追溯段 | `出处` / `来源` | 内容 |

## 锁定矩阵（MANDATORY）

同一编码在任何时刻只指向同一事物。下表是要素 × 状态的权限（含改什么走哪条通道）。四态定义见 [status-definitions.md · 标准四态](status-definitions.md#标准四态唯一生命周期状态集合)；版本号递增时机见同文件 [变更流程与版本号](status-definitions.md#变更流程与版本号统一mandatory)。

| 要素 | `初稿` | `正式` | `草案` | `废弃` |
|------|--------|--------|--------|--------|
| **编码 ID / 类型码** | **MUST NOT**（类型码用错 → 作废后新建，原编号永不复用） | **MUST NOT** | **MUST NOT** | **MUST NOT**（编号永不复用） |
| **标题** | **可改**，但 **MUST** 先扫描全部引用处并同步修改 | **MUST NOT**（唯一通道：`废弃` + 新增编码） | **MUST NOT**（唯一通道：`废弃` + 新增编码） | **MUST NOT** |
| **业务含义 / 判定口径** | 可直接修改 | 根本变化 → 废弃 + 新增；小范围澄清且不改变对外承诺 → 走解冻通道 | 可直接修改 | 只读 |
| **正文 / 属性 / 追溯关系** | 可原地编辑，**不递增版本号** | 锁定（须先解冻为 `草案`；**解冻时**递增版本号） | 可原地编辑，**不递增版本号** | 只读 |
| **存在性** | **MUST NOT** 删除；可**作废**（→ `废弃`，`废弃原因` 记「初稿期作废」、细项 `修订版本号` 保持 `1`） | **MUST NOT** 删除，只能 `废弃`（见 [item-deprecation.md](item-deprecation.md) / [doc-deprecation.md](doc-deprecation.md)） | **MUST NOT** 删除；只能 `回退`（→ `正式`）或 `废弃`（最后版本号 = 该草案号） | 文档：原地标废弃 + **建议归档日期**，到期移入 `deprecated/`；细项：**原地保留，不移除、不删除** |
| **记录型字段** | 可追加 / 修改 | **可追加 / 修改**（不解冻、不变号） | 可追加 / 修改 | 可追加 |
| **流转伴随字段** | 创建动作写入初值（`v1.0` / `1` / 当天），此后 **MUST NOT** 单独改 | **MUST NOT** 单独改（只有解冻动作写它们） | 解冻那一刻由转换写入，本轮内 **MUST NOT** 再改 | **MUST NOT** 改（终态时间由 `废弃时间` 记录） |

- **引用同步义务**：`初稿` 期改标题前，**MUST** 定位全部引用处（`python3 scripts/check_docs.py --refs {编码}`）并一并修改。作废**不删除**引用——定义块与锚点原地保留；活引用仍 MUST 按 [item-deprecation.md](item-deprecation.md) 标注废弃。
- 锁定与状态**正交**：`状态` 只决定标题能否改、标题之外的内容能否直接改；**编码 ID、类型码与存在性在任何状态下都 MUST NOT 被削弱**。MUST 保留所有已正式化编码的完整历史记录。
- 治理段首行 `细项状态` 属**状态**类；后两行属**流转伴随**，不属上表「正文 / 属性」。
- **缺口 / 计数器**：计数器「下一可用编号」MUST 等于该类型码已用最大编号 + 1，序列 MUST 无缺口（全部分配过的编号，不分状态）。作废项仍占编号，不存在合法缺口；缺口即缺陷，工具报 ERROR。
- 违规三类请求（任意状态下改 ID/类型码；改 `正式`/`草案` 标题；改已 `正式` 的业务含义）：不受理，按上表给通道。响应程序见 [SKILL.md · 处理编码含义变更请求](../SKILL.md#处理编码含义变更请求)。

## 动作

| 动作 | 状态变化 | 版本 / 修订号 | 谁批准 |
|------|----------|---------------|--------|
| 创建 | → `初稿` | 文档 `v1.0`；细项修订号 `1` | 分配流程 |
| 改标题 | `初稿` 原地 | 不变 | 须先 `--refs` |
| 定稿 | `初稿→正式` 或 `草案→正式` | **不递增** | 审核者 |
| 解冻 | `正式→草案` | 文档版本递增；被改细项修订号 `+1` | 对象负责人，须确认 |
| 回退 | `草案→正式` | 文档版本回到解冻前；细项修订号**不回退** | 审核者 |
| 作废 | `初稿→废弃` / `正式→废弃` / `草案→废弃` | 不递增；初稿作废修订号保持 `1` | 见 [status-definitions.md · 状态变更权限](status-definitions.md#状态变更权限) |
| 落实 | 不改 `细项状态` | 不变号 | 写 PLN 记录型字段；新增目标细项仍受层级门控 |

以上动作没有任何一项能**删除**已分配编码或已建档文档。
