# 产品版本与产品基线

产品版本是**产品级**发版标签，与设计对象的[修订版本号](status-definitions.md#变更流程与版本号统一mandatory)正交。产品基线是某一产品版本下**可实现细项**的不可变快照。

本技能 **MUST NOT** 在 README 维护第二份引入/退出总表，**MUST NOT** 在设计文档里登记代码仓库、构建号或包路径。消费方可自行从基线快照衍生「功能特性」视图；技能只维护基线快照本身。

## 产品版本（记录型）

| 项 | 规则 |
|----|------|
| 承载 | 当前作用域 `README.md` 项目元信息字段 `产品版本`，取值 `vX.Y`（如 `v1.0`） |
| 初值 | `v1.0`（尚无基线文件时） |
| 写入 | 仅[升产品版本](#升产品版本mandatory)；**MUST NOT** 随文档/细项解冻、定稿或作废而改 |
| 多应用 | 每个应用级 README 各自一份；顶层多应用 README **MUST NOT** 充当某一应用的产品版本源 |

升产品版本**不解冻**任何设计文档，**不改**修订号，**不改**本文引用钉住表，**不改**定义块上的遗留谱系字段。

默认次版本 `+1`（`v1.3→v1.4`）。主版本只询问，AI **MUST NOT** 自行升主版本。

## 产品基线（MANDATORY）

| 项 | 规则 |
|----|------|
| 含义 | 相对某一产品版本 V：当时允许作为实现依据的细项集合 |
| 成员条件 | `细项状态 = 正式`；**全部类型码**均须纳入（不按 FR/ALG 等裁剪） |
| 非成员 | `初稿` / `草案` / `废弃` **MUST NOT** 进入 `items` |
| 承载 | 作用域目录 `baselines/vX.Y.yaml`（一版本一文件；**MUST NOT** 按大版本合并） |
| SSoT | 产品切片以该文件为唯一真源；对象上的 `引入版本` / `退出版本` 为遗留字段，见[遗留谱系字段](#遗留谱系字段) |

文档（L0–L6 / ADR / REF 整篇）**不是**基线成员单位；整篇 `正式` 只表示文档结构冻结。实现门禁看细项是否在当前基线的 `items` 中。

### 文件布局

```text
ued/{app}/baselines/
  README.md       # 可选：说明历史只读、当前版以应用 README `产品版本` 为准
  v1.0.yaml
  v1.1.yaml
```

单应用模式：`ued/baselines/`。历史文件写完后 **MUST NOT** 再改 `items`；纠错通过升新版完成。检查器对**当前** README `产品版本` 对应文件对照活正式集；历史文件只校验形态与增量三块，不因事后解冻/废弃而报「成员非正式」。

### 快照 schema

```yaml
product_version: v1.1
date: YYYY-MM-DD
note: "可选一句话"
prev: v1.0            # 首版省略或 null

added:   [CODE, ...]  # 相对 prev 新进入 items
removed: [CODE, ...]  # 相对 prev 退出 items
changed: [CODE, ...]  # 两版都在 items，且 revision 变大

items:
  - code: FR-001
    type: FR
    title: "..."
    revision: 2
    doc: L2-001
```

| 块 | 规则 |
|----|------|
| `items` | 该版本完整成员表；按 `code` 字典序；生成时刻全部为 `正式` |
| `added` / `removed` / `changed` | 可由 `prev.items` 与本版 `items` 重算；写入文件便于人读；检查器 MUST 能重算并校验一致 |
| `changed` | **仅**当同一 `code` 的 `revision` 较 prev 增大（解冻代际）；非法内容指纹 |
| 首版 | 无 `prev`：`added` = 全部 `items` 的 code 列表，`removed` / `changed` 为空列表 |

每条 `items` 元素字段：`code` / `type` / `title` / `revision` / `doc`（定义该细项的文档编码）。

### 生成手法（推荐）

后期成员多、每版变更少时：

1. **真源**仍是当前 `ued/` 中全部 `细项状态=正式` 的细项（不是上一版 YAML 本身）。
2. **手法**：以 `prev` 快照为底稿复制到新版本号 → 按扫描结果增删改 → 写出完整 `items`。
3. **校验**：写出的 `items` MUST 等于当前正式集；增量三块 MUST 与重算一致。
4. **MUST NOT** 只复制上一版、不对照现状就当新基线。

工具：`check_docs.py --bump-product`（见脚本帮助）。AI 手写时同样按「复制上一版再改差额 + 对照正式集」。

## 升产品版本（MANDATORY）

用户说「发版 / 升产品版本」时执行。Checkpoint 5 若命中下款询问条件，**SHOULD** 问是否同时升。定稿 **MUST NOT** 写基线文件。

1. **定号**：默认次版本 `+1`。首次建立基线、当前仍为 `v1.0` 且尚无 `baselines/` 快照时，MAY 不升号、以 `v1.0` 生成首份快照。
2. **询问主版本（SHOULD，自上次产品版本以来）**：命中任一条则询问，用户否决或未答则保持次版本。条数只决定问不问。
   - L0 目标 / 愿景类细项解冻或新定稿 ≥ 1
   - 新 ADR 定稿，或 ADR 废弃 ≥ 1
   - 有替代编码的废弃 ≥ 1
   - 新定稿的 FR / NFR / DEC ≥ 8，或解冻修订的 FR / NFR / DEC ≥ 5
   - AC / ALG 等支撑细项的条数 **MUST NOT** 拿来问主版本
3. **生成基线快照**（用本步确定后的产品版本）：
   - 扫描作用域全部 `正式` 细项 → 候选 `items`
   - 读上一版 `baselines/{prev}.yaml`（若无则为首版）
   - 按[生成手法](#生成手法推荐)写出 `baselines/vX.Y.yaml`（**新建**；已存在则 MUST 停下请示，不得覆盖）
4. **发版记录**：更新 README `产品版本`；追加一行：产品版本、日期、可选说明（MAY 链接 `./baselines/vX.Y.yaml`）。**MUST NOT** 写 git / svn 标签、构建号、包路径。

## 据文档实现与产品基线

实现门禁见 [SKILL.md · 据文档实现](../SKILL.md#据文档实现消费侧mandatory)：目标细项 MUST 出现在**当前** `产品版本` 对应基线文件的 `items` 中。`正式` 但尚未纳入任何当前基线 → **MUST NOT** 实现（须升产品版本）。

## 遗留谱系字段

定义块 / 文档元信息上的 `引入版本` / `退出版本` 曾用于对象级盖章。自本版起：

- 产品切片 SSoT = `baselines/*.yaml`
- 升产品版本 **MUST NOT** 再向对象写入或改写这两列
- 存量可保留；检查器对遗留字段仅做取值形态校验，并可以 WARNING 提示「谱系已迁 baselines」
- 与基线冲突时以基线为准；格式迁移时可剥掉对象上的两列（不解冻、不加修订号）

## 存量迁移

1. 补 README `产品版本`（若缺）。
2. 用当时全部 `正式` 细项生成首份 `baselines/vX.Y.yaml`（`added`=全量 code，`removed`/`changed`=[]；版本号可沿用已宣布的产品版本，如已有 `v5.17` 则不必改回 `v1.0`）。
3. 可选：剥掉对象上的 `引入版本` / `退出版本`。
4. **MUST NOT** 追溯猜测更早产品切片的正文内容；更早切片以 VCS 历史为准。
