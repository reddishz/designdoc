# 产品版本与发版谱系

产品版本是**产品级**发版标签，与设计对象的[修订版本号](status-definitions.md#变更流程与版本号统一mandatory)正交。本技能只提供谱系信息，**MUST NOT** 定义或维护「功能特性清单」一类衍生视图，**MUST NOT** 在设计文档里登记代码仓库、构建号或包路径。

## 产品版本（记录型）

| 项 | 规则 |
|----|------|
| 承载 | 当前作用域 `README.md` 项目元信息字段 `产品版本`，取值 `vX.Y`（如 `v1.0`） |
| 初值 | `v1.0` |
| 写入 | 仅[升产品版本](#升产品版本mandatory)程序；**MUST NOT** 随文档/细项解冻、定稿或作废而改 |
| 多应用 | 每个应用级 README 各自一份；顶层多应用 README **MUST NOT** 充当某一应用的产品版本源 |

升产品版本**不解冻**任何设计文档，**不改**修订号，**不改**本文引用钉住表。

默认次版本 `+1`（`v1.3→v1.4`）。主版本只询问，AI **MUST NOT** 自行升主版本。

## 引入版本 / 退出版本（发版谱系）

每个已进入产品基线的设计对象记录两个点，消费方据此自行筛选（例如只要 FR）。

| 字段 | 对象 | 含义 |
|------|------|------|
| `引入版本` | 全部编码细项（定义块发版谱系段）；L0–L6 / ADR / REF 文档（元信息表） | 该对象随哪一版产品进入基线（含） |
| `退出版本` | 同上 | 从哪一版产品起不再在役（不含）；空 = 仍在役 |

在役区间：`[引入版本, 退出版本)`。例：引入 `v1.2`、退出 `v1.6` → 在 `v1.2`–`v1.5` 工作。

- 文档与文内细项**独立盖章**：文档仍在役时，其中某细项可以已退出；后加的细项可以比文档更晚引入。
- `初稿` 与初稿期作废 **MUST NOT** 写 `引入版本` / `退出版本`（从未进入产品基线）。
- **MUST NOT** 在定稿、解冻或再定稿时写入或改写这两列。写入时机只有升产品版本时的盖章。盖章后 `引入版本` **MUST NOT** 再改；`退出版本` 只写一次。
- **MUST NOT** 罗列「曾在哪些产品版本里被修订」；修订看修订号与变更记录。
- 本文引用 **MUST NOT** 钉产品版本。

未盖章可缺行。缺盖章本版检查器不 ERROR。

## 升产品版本（MANDATORY）

用户说「发版 / 升产品版本」时执行。Checkpoint 5 若命中下款询问条件，**SHOULD** 问是否同时升。

1. **定号**：默认次版本 `+1`。首次纳入产品基线、当前仍为 `v1.0` 且尚无发版记录时，MAY 不升号、以 `v1.0` 盖章作为首个产品基线。
2. **询问主版本（SHOULD，自上次产品版本以来）**：命中任一条则询问，用户否决或未答则保持次版本。条数只决定问不问。
   - L0 目标 / 愿景类细项解冻或新定稿 ≥ 1
   - 新 ADR 定稿，或 ADR 废弃 ≥ 1
   - 有替代编码的废弃 ≥ 1
   - 新定稿的 FR / NFR / DEC ≥ 8，或解冻修订的 FR / NFR / DEC ≥ 5
   - AC / ALG 等支撑细项的条数 **MUST NOT** 拿来问主版本
3. **盖章**（用本步确定后的产品版本）：
   - 所有 `正式` / `草案` 且无 `引入版本` 的细项与文档 → 写入本版引入（`草案` 必经 `正式`，发版时若尚未盖章按本版引入；`初稿` 与初稿期作废 **MUST NOT** 盖）
   - 所有已 `废弃`（非初稿期作废）且无 `退出版本` 的细项与文档 → 写入本版退出
4. **发版记录**：在作用域 README 追加一行：产品版本、日期、可选一句话说明。SSoT 是对象上的两列；**MUST NOT** 在 README 维护第二份引入/退出总表，也 **MUST NOT** 写 git / svn 标签、构建号、包路径。

## 存量迁移

规范对齐口径见 [status-definitions.md · 存量文档迁移](status-definitions.md#存量文档迁移)。`引入版本` / `退出版本` 从此后第一次升产品版本起盖，**MUST NOT** 追溯猜测。
