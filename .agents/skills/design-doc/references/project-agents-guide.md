# 项目接入：根 AGENTS.md 托管块与常驻规则

design-doc 技能靠宿主按 `description` 判断是否加载，**不保证每次都触发**；Agent 读过规则也可能在执行顺序上违规。因此接入要落下两样常驻入口，宿主每次会话都会读到：

| 入口 | 位置 | 作用 |
|------|------|------|
| 托管块 | 项目根 `AGENTS.md` 内 design-doc 标记块 | 声明采用 design-doc，写明硬性顺序与 Gate 入口 |
| 常驻规则 | 项目 `.cursor/rules/design-doc-bootstrap.mdc`（`alwaysApply: true`） | 每次会话注入一句提醒，指向托管块；不依赖技能是否被匹配 |

两者都**不复制规则正文**，细则永远在技能包里。托管块和规则都只是入口；它们**不能保证**行为，接入是否成功要靠冒烟验证。

## 接入检查清单

接入（或「检查接入」）按下列顺序逐项确认，缺哪项补哪项。每次写入前都要向用户说明内容并取得确认：

1. 确认项目采用 design-doc：存在设计目录（默认 `ued/`），或用户明确要采用但尚未建立。
2. 确认技能已安装：`.agents/skills/design-doc/SKILL.md` 存在。
3. 根 `AGENTS.md` 含托管块，块号与正文与已装技能一致（见下文「写入规则」）。
4. 项目根存在常驻规则 `.cursor/rules/design-doc-bootstrap.mdc`，源文件为 `assets/snippets/design-doc-bootstrap.mdc`。
5. 有旧式章节（上一版指南生成的「设计文档优先」）则迁移，见「旧式章节迁移」。
6. 填好块外占位（见「块外内容」）。
7. 运行检查器（不带 `ued/` 时也可运行）：`python3 .agents/skills/design-doc/scripts/check_docs.py -p <设计目录>`，AGENTS 与常驻规则相关问题全部消除。
8. 通过[冒烟验证](#冒烟验证)。

**接入完成的标准是通过冒烟验证，不是文件生成完成。**

## 托管块

块源文件：[assets/snippets/agents-block.md](../assets/snippets/agents-block.md)。整块原样写入项目 `AGENTS.md`，标记独占一行：

```text
<!-- design-doc:begin block=N -->
...
<!-- design-doc:end -->
```

`block=N` 是**块修订号**，块正文变化时递增，与规范版本无关。检查器比对块号**和**块正文：块号不同即落后或超前；块号相同但正文不同（被手改，或技能块改了却未递增）同样报 WARNING。因此块正文只能整块替换，**不得在块内加项目个性化内容**。

## 写入规则

- **AGENTS.md 是用户文件。** 首次写入或更新前，**MUST** 向用户说明将写入的内容并取得确认。
- **无 `AGENTS.md`**：新建，写一个 H1，再写入整块。
- **已有 `AGENTS.md` 无块**：在末尾追加整块；**MUST NOT** 改块外内容（旧式章节见下节）。
- **已有块，块号落后或正文不一致**：只替换起止标记之间（含标记）的整块，块外内容原样保留。
- **常驻规则**：无该文件则写入源文件；已有且内容不合格（缺 `alwaysApply: true` 或未指向 design-doc）则重写。写入前同样须确认。

## 旧式章节迁移

上一版指南生成的 `AGENTS.md` 常含一节未带标记的「设计文档优先（有 ued/ 时 MUST）」。它与托管块并存会出现两套规则。检查器报「AGENTS.md 含旧式设计优先章节」时：

1. 向用户列出该节原文，说明将删除并由托管块替代。
2. 用户确认后，删除该节，并把托管块放在它原来的位置（或文件末尾）。
3. 其余块外内容不动。

## 块外内容

块外是项目自己的地方，写入项目特有信息，不要写进块：

- 项目编码（来自 `ued/README.md` 项目元信息）；
- 设计目录路径，若不是默认 `ued/`；
- 当前产品版本（来自 `ued/README.md` 的 `产品版本`）；
- 项目其他约定（构建、测试、提交规范等，与 design-doc 无关的内容）。

## 多子系统变体

系统根的 `ued/README.md` 含子系统注册表时，仍只在**项目根**放一份 `AGENTS.md`、一份托管块和一份常驻规则。托管块第 7 条已说明路由，块外可补充子系统清单。

## 其他宿主

Cursor 之外的宿主不读 `.cursor/rules/` 时，在它们的常驻入口（如 `CLAUDE.md`）放一句指向 `AGENTS.md` 的引用，不复制块正文。`AGENTS.md` 必须存在，检查器只读它。

## 冒烟验证

给 Agent 一条典型请求，例如「把某功能的行为改成……」或「修一下某个缺陷」，期望的第一步是：

- 先读托管块指向的 Gate 文件，并输出 Gate 记录（设计依据、基线、状态、判定、后续动作）；
- **没有**先改代码，**没有**先改设计目录。

失败时按顺序排查：`AGENTS.md` 是否在项目根且被宿主加载；常驻规则是否在 `.cursor/rules/` 且为 always-apply；技能路径是否可发现；块是否完整。修好后重测。

冒烟验证是对话行为的人工验收，无法脚本化。检查器只能证明块存在、块与已装版本一致、规则存在。

## 检查器报告

`check_docs.py` 在项目根查找 `AGENTS.md` 与常驻规则。项目根按位置推定：单系统为设计目录的上一级；子系统 `ued/{subsystem}/` 为 `ued/` 的上一级；仓库根（含 `.git` 或 `.svn` 的最近祖先）也被接受。无设计目录时仍检查。

| 问题名 | 级别 | 含义 |
|--------|------|------|
| 项目缺 AGENTS.md | WARNING | 项目根没有 `AGENTS.md` |
| AGENTS.md 缺设计优先托管块 | WARNING | 有 `AGENTS.md` 但没有 design-doc 托管块 |
| AGENTS.md 托管块不完整 | WARNING | 起止标记缺失、重复、顺序错，或 `block=N` 缺失 |
| AGENTS.md 托管块落后 | WARNING | 块号低于已装技能；按本文整块更新（须确认） |
| AGENTS.md 托管块正文不一致 | WARNING | 块号相同但正文不同；按本文整块替换（须确认） |
| AGENTS.md 托管块超前 | ERROR | 块号高于已装技能；技能回退或版本不一致 |
| AGENTS.md 含旧式设计优先章节 | WARNING | 块外残留未带标记的旧章节；按「旧式章节迁移」处理 |
| 缺 design-doc 常驻规则 | WARNING | 没有 always-apply 常驻规则，或规则文件内容不合格 |

检查器不做语义检查：块外是否有与 design-doc 冲突的旧规则，只能靠人审。
