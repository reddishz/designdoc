# 生命周期：废弃与定稿收尾

> 作废细项/整份文档，或本轮实质修改收尾（Checkpoint 5）时加载。

**MUST 另读（按需）**：[`item-deprecation.md`](../item-deprecation.md)、[`doc-deprecation.md`](../doc-deprecation.md)、[`status-definitions.md`](../status-definitions.md)、[`product-version.md`](../product-version.md)。

## Checkpoint 总表

| Checkpoint | 时机 | 暂停条件 |
|------------|------|----------|
| 1 | 生成初稿后 | 确认大纲与核心细项 |
| 2 | 分配编码 / 增量能力 | 批量新增、核心规则变更，或上层需同步 |
| 3 | 大规模变更或废弃前 | 二次确认 |
| 4 | 标注 `废弃` 或受控复活前 | 确认 `废弃类别` + 一句话原因 + 替代方案；复活须逐条满足条件 |
| 5 | 本轮实质修改收尾 | 提交提示 + 定稿确认 + 基线漂移 |

写作门禁：引用只用编码；可独立语义先落码；章节编号引用即 A 级阻断；未过门禁不得正式发布。

## 废弃细项（Checkpoint 4）

标注前 **MUST** 暂停确认 `废弃类别`（封闭枚举）、一句话 `废弃原因` 与 `替代方案`（ID 与标题规则见 [item-deprecation.md · 废弃类别](../item-deprecation.md#废弃类别封闭枚举mandatory)）。`草案` 可直接废弃；`初稿→废弃` 修订号保持 `1`、`废弃类别` 取 `初稿作废`。**MUST NOT** 以删除代替作废。标记后按须人审列出引用方，确认后再改指或级联。整份文档另见 [整份废弃的前置](../doc-deprecation.md#整份废弃的前置mandatory)。

## 受控复活（Checkpoint 4）

`废弃→草案` **不是**自由操作。**MUST** 先按 [status-definitions.md · 废弃后受控复活](../status-definitions.md#废弃后受控复活受控mandatory) 逐条举证：需求基本不变、原废弃原因已消除、无生效替代、未归档或可确认误归档。任一不满足 → 新建对象 + 新编码，**MUST NOT** 借旧编码。

确认后：`废弃→草案`、`修订版本号` `+1`、写 `复活时间`、保留原废弃登记、清除 `退出版本` 缓存；文档复活按细项粒度（只复活确需继续使用的细项）；同步清单 / 索引 / 钉住行。**MUST NOT** 直接到 `正式`。

## 废弃整份文档

两阶段：原地标 `废弃` + `废弃类别` / 一句话原因 / 替代方案 / 影响范围 + 建议归档日期 → 到期入本作用域 `deprecated/`（只归档不删除）。标注前全部细项须已废弃；用户要求整份废弃但活内容仍在时 **MUST** 停下列缺口。流程见 [doc-deprecation.md](../doc-deprecation.md)。

## 修改完毕：定稿确认与提交提示（Checkpoint 5）

AI **MUST NOT** 自行升格。

**时间戳前置（MUST）**：本轮改过的文档 `最后更新` 刷为当天；`创建日期` 创建后不改。细项 `最后修订日期` 只随修订号递增那天动。改已 `正式` 细项则文档须同轮解冻并 +1。

1. **提交提示**：是否提交 git/svn。「暂不提交」则跳过 2–5。
2. **未冻结扫描**：仅本轮 AI 改过的文件，收集 `初稿`/`草案`。
3. **呈现与确认**：表列未冻结对象；**MUST** 附「未冻结或未入当前产品基线不得作为实现依据」。
4. **升格与提交**：确认者 → `正式`（定稿不加修订号；**定稿不写** `baselines/`）。升格自底向上。细项/文档定稿按须人审与[本文引用 · 文档定稿](../coding-system.md#审查与定稿时机)。再按指示 commit。
5. **基线漂移（MUST 呈现）**：未选暂不提交时，按 [漂移](../product-version.md#相对当前基线的漂移) 列短表。无基线→问首份；仅 revision 落后→建议 **PATCH**；有成员进出→建议 **MINOR**；命中条件再问 **MAJOR**。无漂移不追问。**MUST NOT** 未经确认 `--bump-product`。

**MUST NOT**：未经确认升格；扫并提交本轮未改的历史未冻结对象；删除已分配编码（放弃走作废）。

定稿前 **MUST** 确认本包与 `ued/` 内无未解消的规范/文档冲突（见 SKILL「一致性」）；有冲突当轮修正，**MUST NOT** 用优先级表掩盖。
