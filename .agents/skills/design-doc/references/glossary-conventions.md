# 术语和概念规范

本规范定义项目内**术语**（专有名词、领域术语与概念）的登记、定义与引用方式。术语不是设计细项，不分配编码；它解决的是「同一个词在全项目只有一个意思」。

## 核心原则

- **单一定义**：每个术语在项目内**有且只有一个权威定义**，承载位是某份文档的「术语和概念」章节。其他文档只引用或直接使用，**MUST NOT** 重复定义。
- **全局可索引**：所有已定义术语 **MUST** 登记在**唯一的全局术语表**中，并从表内指回定义文档。
- **冲突即错误**：同一系统内同名术语含义不同，说明术语定义或使用本身有问题。**MUST NOT** 用第二张表、应用命名空间或「以本文为准」来并存两种含义；应改名、加限定语，或统一为一义。
- **表不分配编码**：术语、术语表均不占用 `{类型码}-{序号}`。正文直接写名称，**MUST NOT** 为术语造编码。

## 全局术语表

### 位置与唯一性

- 全局术语表**固定为 `ued/glossary.md`**，单应用、多应用、含 `shared/` 的作用域都只有这一份。
- **MUST NOT** 放到 `ued/{app-name}/` 或 `shared/` 下，也 **MUST NOT** 按应用拆分多份。
- 多应用共用同一张表；某应用的专有术语同样登记在这里。若两个应用需要同名不同义，按「冲突即错误」处理，**MUST NOT** 用两张表并存。
- `ued/README.md` **MUST** 登记指向 `glossary.md` 的链接；其他文档按普通交叉引用规则使用术语名称即可。

### 文档性质与修订

术语表是**辅助文档**：不做生命周期管理（无 `状态`、不进入四态），但**仍是文档**，遵守通用的修订与记录规则。

| 项 | 要求 |
|----|------|
| 文档编码 | **不分配**；不进入文档索引、编码计数器与全局编码索引 |
| 元信息 | `修订版本号`、`作者`、`创建日期`、`最后更新` |
| `修订版本号` | 新建为 `1`；每次**实质变更** `+1`，不得跳号、不得改小；非实质维护可写 `N（维护）` 行而不变号 |
| `变更记录` | 必填，倒序；首行为当前 `修订版本号`（维护行置于同号语义行之上），列为 `修订版本号、日期、作者、变更说明` |
| 纯格式调整 | 不计修订、不追加变更记录，只更新 `最后更新` |

- **实质变更**指术语行的增、删、改（含名称、定义摘要、定义位置）。术语表的修订号不依赖状态转换：它没有 `正式→草案` 解冻动作，内容变更即 `+1`。这是对[状态定义](status-definitions.md)「修订号只在解冻/复活时递增」的唯一辅助文档例外。
- **非实质维护**（如修正《补充信息》中的错字、链接文本）可写 `N（维护）` 行，说明按维护批次格式（见 [status-definitions.md · 维护性变更](status-definitions.md#维护性变更第三维度mandatory)）；术语名称、定义摘要、定义位置的改动 **MUST** 视为实质变更并 `+1`。
- `变更记录` 是记录型字段，**MUST** 完整保留，**MUST NOT** 删改历史行。

### 表结构（固定四列）

```markdown
| 中文名称 | 英文名称 | 定义 | 定义位置 |
|----------|----------|------|----------|
| 订单 | Order | 客户提交的购买请求，是履约的起点。 | L2-003 |
```

| 列 | 必填 | 口径 |
|----|------|------|
| `中文名称` | 是 | 术语的中文名称；不得为空 |
| `英文名称` | 是 | 术语的英文名称；不得为空。两种语言都 **MUST** 具备 |
| `定义` | 是 | **索引级摘要**（一到两句），帮助读者判断是否为目标术语；完整定义在 `定义位置` 指向的文档 |
| `定义位置` | 是 | **完整文档编码**（启用项目编码时含前缀，如 `CRM-L2-003`）；指向承载该术语权威定义的文档 |

- `定义位置` **MUST** 写文档编码，**MUST NOT** 写文件名、路径、章节号或锚点；具体定位由目标文档内的术语块承担。
- 目标文档 **MUST** 在该文档的「术语和概念」章节定义该术语；只登记、无定义视为悬空。
- 表**只放固定字段**。`英文标识符`、`补充说明`、`定义来源`、使用注意事项等**可选信息 MUST NOT 增加为列**；放在表后的独立小节中，按术语名称分条补充（见下文《术语的补充信息》）。
- 中文名称、英文名称分别做唯一性校验（英文忽略大小写）。同名术语 **MUST NOT** 出现两行。

### 术语的补充信息

可选信息在术语表之后另起章节，按术语名称组织，不塞进表格：

```markdown
## 补充信息

### 订单

- **英文标识符**：`order`
- **定义来源**：REF-003
- **补充说明**：本系统中订单必须关联履约单；与「购物车」的区别见定义文档。
```

- 只写有必要的条目；无补充信息的术语不必出现。
- 补充信息 **MUST NOT** 改写或覆盖权威定义；它只补充标识符、来源、易混点等**辅助信息**。
- 术语名称变化后，旧名 **MAY** 写进术语表 `变更记录` 对应行的说明（如 `旧称 → 新称`），或本节《补充信息》的普通说明文字；**MUST NOT** 为此新增专用字段、列或属性行。

### 新增与变更

1. **新增**：先确认目标文档已写术语定义，再在全局表加行；两处名称与定义位置一致。
2. **名称调整**：对术语表是**实质变更**（`修订版本号` +1）；对设计文档与细项属[维护性变更](status-definitions.md#维护性变更第三维度mandatory)（写 `N（维护）` 行、不变号）。执行时 **MUST** 同步定义文档、全局表、`所用术语` 与正文使用处，避免旧名残留；旧名写进变更记录说明或《补充信息》的普通文字，**MUST NOT** 另设字段；跨文档调整 **MUST** 使用同一维护批次号。
3. **删除**：只有确认全项目不再使用、且定义文档已移除该术语块后才可删除；删除同样是实质变更。
4. **冲突**：发现同名不同义，先停止登记并按「冲突即错误」收口；**MUST NOT** 用别名表绕过。

## 文档「术语和概念」章节

### 何时写、放在哪

- **可选**：只定义**本文档引入或确立**的术语；没有就不写该章节，也不要写「无」占位。
- 写成**顶层章节** `## 术语和概念`，位置在元信息表之后、第一个编号章节之前，便于读者先对齐用词。
- **MUST NOT** 用表格承载定义；定义可能较长，使用**段落结构**。
- 该章节的术语块**不是设计细项**：不写 `细项状态` / `修订版本号` / `创建日期`，不进入「本文档细项编码清单」、全局编码索引或编码计数器。

### 单个术语块

````markdown
### 订单

- **中文名称**：订单
- **英文名称**：Order
- **英文标识符**：order
- **定义来源**：REF-003

**定义**：本系统中，订单是客户提交的购买请求，是履约与结算的起点。

**补充说明**：订单必须关联一条履约单；无履约单的购买请求不构成订单。

**澄清与对比**：与「购物车」不同，订单已经过提交确认并生成履约义务；本系统中的「单据」是更上位的概念，不特指订单。
````

| 项 | 必填 | 口径 |
|----|------|------|
| 标题 | 是 | `###` 标题，**MAY** 用中文名称或英文名称；**MUST** 与下方某个名称字段一致 |
| `中文名称` | 是 | 非空 |
| `英文名称` | 是 | 非空；两种语言都 **MUST** 具备 |
| `定义` | 是 | 非空；**这是该术语的权威定义**，可多段 |
| `英文标识符` | 否 | 代码中的稳定标识；无则删行 |
| `定义来源` | 否 | 外部依据（如 `REF-003`）；无则删行 |
| `补充说明` | 否 | 独立段落，不挤进属性行 |
| `澄清与对比` | 否 | 独立段落，见下文 |

- 标题用哪种语言都可以，但两种名称都必须写全。**MUST NOT** 只写中文或只写英文。
- 旧名不单设字段：需要时写进 `变更记录` 行说明或 `补充说明` 的普通文字；当前名称仍以 `中文名称` / `英文名称` 与术语表行为准。
- `定义` 之后的可选信息 **MUST** 另起段落，或用比术语标题更深的子标题；**MUST NOT** 并入 `定义` 行尾或表格单元格。
- 同一文档 **MUST NOT** 定义同名术语两次；同一项目 **MUST NOT** 由两份文档同时定义同一术语。

### 澄清与对比

对容易混淆的术语，**SHOULD** 在定义之后写一段澄清，至少覆盖适用的情形：

- 容易与哪些相邻概念混淆，区别在哪；
- 在本系统/本设计中它被**固定**为什么含义；
- 它**不是**什么（常见误解）。

澄清是定义的补充，**MUST NOT** 另立一套与 `定义` 冲突的说法；发现冲突时先修正 `定义`。

## 文档元信息：所用术语（可选）

文档可在元信息表增加一行，列出本篇**重点使用**的术语：

```markdown
| 所用术语 | 订单、履约、库存 |
```

- 只用**逗号或顿号**分隔名称，**MUST NOT** 加链接、编码、括号说明或表格语法。
- 只列重点术语，不要求穷举；通用词汇、未在本项目定义的一般用语不列。
- 每个名称 **MUST** 能在全局术语表中找到（中文或英文名称均可）；找不到时，要么补登记并给出定义位置，要么它不属于本项目术语，应从本行删除。
- 本文档在「术语和概念」中**定义**的术语由该章节承载，**SHOULD NOT** 在 `所用术语` 中重复。
- 没有全局术语表时 **MUST NOT** 使用本行——没有可解析的定义位置。

## 使用与引用

- 正文直接使用术语名称；**MUST NOT** 为术语插入编码或锚点。
- 首次出现且有助于理解时，可按普通交叉引用规则链接到定义文档；**SHOULD NOT** 在多处复制完整定义。
- 引用他文档定义的术语时，只写名称或指向定义文档，**MUST NOT** 在本文件重写一份「本地定义」。
- 发现术语含义需要变化时，先改**定义文档**，再同步全局表摘要；**MUST NOT** 只在某个使用处就地改含义。

## 与 `DOM` 的关系

- `DOM` 是可选的设计细项，用于结构化表达核心概念（属性、关系、约束）；它**不替代**术语定义。
- 一个概念可以同时有术语定义与 `DOM`：术语定义回答「这个词指什么」，`DOM` 回答「这个设计对象由什么构成」。两者分工不同，**MUST NOT** 互相复制长文；术语块可引用 `DOM` 编码。
- **MUST NOT** 为了给术语一个「编码」而强行创建 `DOM`；术语表本身不分配编码。

## 校验口径

`check_docs.py` 在存在 `ued/glossary.md` 时启用术语检查；无术语表但出现术语章节或 `所用术语` 时按错误处理。

| 检查 | 级别 | 问题名 | 说明 |
|------|------|--------|------|
| 全局术语表唯一 | ERROR | `术语表位置非法` | 只允许 `ued/glossary.md` 一份；应用目录下的同名文件、或不在该路径的 `glossary.md` 均违规 |
| 无表却用术语 | ERROR | `缺少全局术语表` | 出现术语章节或 `所用术语`，但项目没有 `ued/glossary.md` |
| 元信息必填 | ERROR | `术语表元信息缺失` | 缺 `修订版本号` / `作者` / `创建日期` / `最后更新` |
| 修订号格式 | ERROR | `术语表修订号非法` | `修订版本号` 不是单个正整数 |
| 日期格式 | WARNING | `术语表日期格式错误` | `创建日期` / `最后更新` 不是 `YYYY-MM-DD` |
| 不参与四态 | WARNING | `术语表含编码或状态字段` | 术语表出现 `文档编码` 或 `状态` 字段 |
| 变更记录 | WARNING | `术语表缺变更记录`、`文档修订号与变更记录不一致`、`变更记录未按修订号倒序`、`维护行说明格式错误` | 缺 `变更记录`，或修订号与最新语义行不一致、历史行未倒序、维护行说明不合批次格式 |
| 固定四列 | ERROR | `术语表缺少固定四列表`、`术语表列不合规` | 表头缺 `中文名称` / `英文名称` / `定义` / `定义位置`，或出现额外列（可选信息应放到表后小节） |
| 字段必填 | ERROR | `术语表字段缺失` | 某行的固定列有空值 |
| 名称唯一 | ERROR | `术语名称重复` | 同名术语出现多行；中文按原文、英文忽略大小写比较 |
| 定义位置可解析 | ERROR | `术语定义位置非法` | `定义位置` 不是完整文档编码，或目标文档不存在 |
| 定义位置正确 | ERROR | `术语定义位置错误` | 术语实际定义在另一份文档，`定义位置` 指错 |
| 定义存在 | ERROR | `术语定义未找到` | 目标文档的「术语和概念」中没有该术语 |
| 定义唯一 | ERROR | `术语重复定义` | 同一术语在同一文档重复定义，或跨文档各定义一次 |
| 定义已登记 | ERROR | `术语未登记` | 文档定义了术语，但全局表没有对应行 |
| 术语块字段 | ERROR | `术语定义缺失`、`术语标题与名称不一致` | 缺 `中文名称` / `英文名称` / `定义`，或标题不等于任一语言名称 |
| 术语章节结构 | WARNING | `术语章节重复`、`术语章节层级错误`、`术语章节位置靠后` | 一个文档只能有一个顶层 `## 术语和概念`，且位于第一个编号章节之前 |
| 术语章节禁表格 | ERROR | `术语章节使用表格` | 定义块 MUST 用段落，MUST NOT 用表格 |
| 旧标题迁移 | INFO | `术语章节标题待迁移` | 旧名 `术语与概念`，建议改为 `术语和概念` |
| 所用术语格式 | ERROR | `所用术语含链接或编码` | `所用术语` 只写逗号/顿号分隔的名称，不得加链接、编码或表格语法 |
| 所用术语可解析 | ERROR | `所用术语无法解析` | `所用术语` 中的名称不在全局表 |
| 所用术语不重复 | INFO | `所用术语重复本文定义` | 本文已定义的术语 SHOULD NOT 再列入 `所用术语` |
| README 入口 | WARNING | `README未登记术语表` | 存在术语表但 `ued/README.md` 未链接 `glossary.md` |

- 术语章节内的定义块不被当作细项编码检查，也不参与细项状态门控。
- 术语表自身的修订检查只覆盖可机检的不变式；「是否实质变更」由作者判断。

## 存量迁移

| 存量写法 | 迁移为 |
|----------|--------|
| 文档内 `术语与概念（可选）` 表格 | 改为顶层 `## 术语和概念`，每条术语改写为段落块（补齐英文名称与 `定义`） |
| 应用目录下的 `glossary.md` | 合并到 `ued/glossary.md`；同名冲突先统一含义，**MUST NOT** 保留两张表 |
| 全局表 `术语 \| 定义 \| 备注` | 改为固定四列；`备注` 移入表后的《补充信息》，并补 `定义位置` |
| 术语表 `v1.0` 式版本 | 改为整数 `修订版本号`，按实质变更顺位映射；**MUST NOT** 把 `v2.0` 写成 `2` |

- 迁移属格式调整时，设计文档**不解冻、不加修订号**；术语表本身若为首次建立，修订号从 `1` 起。
- 全局表建立后，原文档术语表格中的重复定义按「单一定义」合并：保留一处权威定义，其余改为名称引用。
