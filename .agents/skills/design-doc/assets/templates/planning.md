> 2. **单一状态字段**：PLN 只用 `细项状态` 表达生命周期，取标准四态 `初稿/正式/草案/废弃`（新建默认 `初稿`；历史文档缺此字段时按 `变更记录` 判定，无法判定取 `草案`）；**MUST NOT** 另设 `规划状态` 等与生命周期重叠的第二套枚举。**想法是否已展开由 `落实情况`（`未落实` / `已落实`）表达，与状态正交**；规划处置由记录型字段 `落实情况` / `落实记录` / `废弃原因` / `建议复审日期` 承载，**变更它们不改版本号**
> 3. **编码形式与项目前缀**：见文首说明
> 4. **本文档细项编码清单**：规划总览提供 PLN 全局登记视图，定义块在各自所属层级文档（默认 L2）
> 5. **定论与落实两条路径**：想法**定论即定 `正式`**（与是否已展开无关）；展开为具体细项时置 `落实情况：已落实` 并写 `落实记录`（日期 + 目标细项编码），同时在该目标细项的定义块加 `来源` 属性行回指本 PLN，**PLN 本身保持 `正式`**（落实本身不是废弃，它成为历史规划档案）；不再纳入者标 `细项状态：废弃` 并写 `废弃原因`；已落实的想法连同其落地物一并被推翻时亦走 `废弃`，此时 `落实情况` **保留事实值 `已落实`**、`废弃原因` 记推翻依据；仍处 `初稿`（从未定稿）即放弃者**直接删除**并回收编号、同步清理引用与索引（见 `references/coding-system.md` · 《规划项生命周期》）
> 6. **复审兜底**：`落实情况` 为 `未落实` 且 `细项状态` 非 `废弃` 的 PLN **MUST** 填 `建议复审日期`，与「重新考虑的条件」互补（条件 = 被动触发信号，日期 = 主动时间兜底）；到期只提示复核、**不自动改状态**，处置（展开 / 延后并更新日期 / 废弃）由人决定；置 `已落实` 或 `废弃` 后置「无」或移除该列值
> 7. **禁止记录执行信息**：不得在本模板及其 PLN 项中写入工时、工作量、负责团队、排期、完成进度等字段；这些属于研发任务管理范畴。`建议复审日期` 是**复审提醒**而非交付承诺，不属此列
> 8. 关联文档引用对应的 L0 文档编码
> 9. 维护细项编码清单和变更记录；变更记录按版本号或日期倒序，最新置顶
>
