> **模板：ADR - 架构决策记录**
>
> **定位**：ADR 是宏观架构级决策的**一事一档**，承载「为什么这么选」；具体事项级决策用 `DEC` 细项。二者的切分轴与判别口诀见 [coding-system.md · ADR 与 DEC 的定位](../../references/coding-system.md#adr-与-dec-的定位)；存放位置见 [layer-system.md · 层级定义](../../references/layer-system.md#层级定义)（与所属层级文档同目录平放，**不设** `adr/` 子目录）。
>
> **使用说明**
>
> 1. 替换 `{编号}`、`{决策标题}` 等占位符
> 2. 状态值从 `初稿/正式/草案/废弃` 中选择；**新建默认 `初稿`**（缺字段时按 `变更记录` 判定：有定稿条目 → `草案`，从未定稿 → `初稿`，无法判定 → `草案`）。ADR **不设专属枚举**：原「采纳」= `正式`（已冻结基线），原「拒绝」= `废弃` + `废弃原因`，原「取代」= `废弃` + `替代方案`；`正式` 后的实质修订需先解冻为 `草案` 并**在解冻时递增版本号**（同步更新元信息表 `版本` 与 `最后更新`，见 [status-definitions.md](../../references/status-definitions.md)）
> 3. **层级与存放目录**：ADR 归属 **L3 概念架构**，`层级` 字段固定填 `L3 - 概念架构`，文件存于 `L3-architecture/`（**MUST NOT** 单设 `adr/` 子目录）——ADR 论证的是「怎么组织系统」，L2 表达「做什么」、不承载架构论证；只是需求级取舍的用 `DEC` / `PRN` 细项而非 ADR（依据见 [layer-system.md · 层级定义](../../references/layer-system.md#层级定义)）
> 4. **编码形式与项目前缀**：见文首说明
> 5. **本文档细项编码清单**：仅本文档范围；分配前检索当前作用域 `README.md` 全局索引，分配后同步更新
> 6. **DEC 分配为可选**：《决策》小节默认只写叙述性文字；仅当该决策需被其他文档以编码引用为契约时才分配 `DEC`。不分配时 MUST 删除《决策》内的定义块与清单中的 DEC 行
> 7. **定义块形态与锚点**：若分配 DEC，MUST 按「`<a id>` 锚点行 + 标题行（全角冒号分隔）+ 具名属性行」书写，房规见 [coding-system.md · 细项定义块形态](../../references/coding-system.md#细项定义块形态mandatory)
> 8. 关联文档引用对应的 L3 文档编码
> 9. 维护细项编码清单和变更记录
>
> **正文边界**：`TEMPLATE:BEGIN` / `TEMPLATE:END` 之间为待复制正文；实例化时删除两行哨兵、只保留其间内容（房规见 [index.md · 模板边界（哨兵）](index.md#模板边界哨兵)）。
