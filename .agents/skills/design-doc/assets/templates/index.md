# 设计文档模板索引

> **说明**：可复制的文档骨架均在本目录（`assets/templates/`）。流程图格式见 [flowchart-guide.md](../guides/flowchart-guide.md)；专项规范见 [references/](../../references/)。

## 编写约定

- **不得包含可执行代码与实现片段**；允许算法、规则、约束、逻辑、流程、状态、假定、接口契约与决策说明等设计性内容。
- **细项编码**：按 [编码体系](../../references/coding-system.md) 执行，默认简洁编码（`{类型码}-{三位序号}`），项目前缀需明确配置。正文中定义的细项须在文末维护**本文档细项编码清单**，并同步更新全局索引。
- **交叉引用**：只允许引用细项编码或文档编码，不得用章节编号定位；正文引用写作 `[{编码}（{标题}）](锚点)`，表格型追溯可写裸编码（完整规则见 [coding-system.md · 交叉引用规则](../../references/coding-system.md#交叉引用规则)）；下层可引用上层，上层无需引用下层。
- **`{当前用户.作者}`**：按当前作用域 `README.md` 的项目元信息解析，解析不到时回落为技能默认值（解析链单点见 [SKILL.md · AI 运行时配置解析规则](../../SKILL.md#ai-运行时配置解析规则)）。
- **术语与概念**：非必填；需要统一名词时见 [glossary-conventions.md](../../references/glossary-conventions.md)，模板中「术语与概念（可选）」小节与项目词汇表二选一或组合使用。

### 模板边界（哨兵）

模板正文 **MUST** 用 HTML 注释哨兵界定，**MUST NOT** 再用 ` ```markdown ` 外层围栏包裹整篇正文——围栏会把正文降级为不可渲染的代码块（标题、表格、`mermaid` 均失效），且与正文内的 ` ```mermaid ` 等嵌套围栏相互破坏。

| 模板类型 | 适用范围 | 容器形态 | 哨兵内正文 |
|----------|----------|----------|------------|
| **整篇型** | L0-L6 / ADR / REF / PLN / README（正文即一份完整文档） | **MUST NOT** 自带 H1；以 `> **模板：{名称}**` 起始的前置 blockquote 承载元信息与使用说明，接 `---` 分隔线 | **MUST** 恰有一个 H1（即目标文档的标题） |
| **片段型** | `project-registry.md`（正文是嵌入宿主文档的片段） | 保留自身标题结构 | 每个可复制片段各自成段 |

- **哨兵写法**：单段用 `<!-- TEMPLATE:BEGIN -->` / `<!-- TEMPLATE:END -->`；多段用 `<!-- TEMPLATE:BEGIN {段名} -->`，段名 **MUST** 与哨兵上方的 `> **{段名}**` 可见标签一致（哨兵参数内不写反引号）。哨兵 **MUST** 成对、不嵌套，各自独占一行。
- **实例化**：AI 复制哨兵之间的内容并**删除两行哨兵**；哨兵外的模板名、元信息与使用说明 **MUST NOT** 进入目标文档。
- **元信息位置**：使用说明 **MUST** 置于哨兵之外（前置），**MUST NOT** 出现在待复制正文内。

## 使用方法

1. **选择模板**：根据文档类型打开上表对应文件
2. **复制内容**：取 `TEMPLATE:BEGIN` / `TEMPLATE:END` 之间的正文为起点编写，**删除两行哨兵**；哨兵外的模板名与使用说明不进入目标文档（细则见《模板边界（哨兵）》）
3. **替换占位符**：更新 `{编号}`、`{文档名称}` 等；仅在当前作用域 `README.md` 已声明 `project_code` 且请求发起方确认时使用 `{项目编码}` 前缀（见 [coding-system.md](../../references/coding-system.md)）
4. **设置状态**：从标准四态中选择；**新建一律默认 `初稿`**（L0-L6 / ADR / REF / PLN 共用同一枚举）
5. **维护编码**：全局唯一；文档末尾维护“本文档细项编码清单”（仅本文档范围），并同步更新当前作用域 `README.md` 全局索引

## 状态值标准

状态值按 [状态定义](../../references/status-definitions.md) 执行：

- **设计文档**（字段名 `状态`）：初稿/正式/草案/废弃，新建默认 `初稿`
- **编码细项**（字段名 `细项状态`，索引/清单列同名）：同上四态，新建默认 `初稿`；与文档状态**同一枚举、不同字段、各自取值**
- **ADR / REF / PLN**：共用同一四态，**不设专属枚举**（ADR 的「拒绝」以 `废弃` + 废弃原因表达，「取代」以 `废弃` + 替代方案表达；REF 的时效信息记在 `来源版本` / `最近核验日期` 等记录型字段）
- **需求追溯**（字段名 `追溯状态`，记录型）：未追溯/已追溯/不适用（L6 只记追溯覆盖关系，不记测试执行结果）
- **应用注册表**（字段名 `状态`，记录型）：取四态（`初稿` 已登记未启用 / `正式` 在用 / `废弃` 已停用）

> 各状态集合、流转与版本号递增时机的完整表述，单点承载于 [status-definitions.md](../../references/status-definitions.md)。

## 结构说明

- **模板**（本目录）：独立 `.md` 文件，按需加载；正文边界由 HTML 注释哨兵界定（见《模板边界（哨兵）》）。
- **专项规范**（[`../../references/`](../../references/)）：编码、层级、状态、审核、废弃等规则完整表述的单点承载处；本目录与其他文件出现不一致时视为规范缺陷，当轮修正。
