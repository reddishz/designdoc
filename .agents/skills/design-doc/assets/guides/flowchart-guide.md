# 流程图格式规范示例

## 格式选择原则

根据流程复杂度选择合适的表示方式：

### 1. 简化箭头形式（单行流程）

**适用场景**：
- 无分支的线性流程
- 无跳转和循环
- 步骤数量较少（建议 ≤ 5 步）

**示例**：
```
用户登录 → 身份验证 → 权限检查 → 进入系统
```

```
需求分析 → 系统设计 → 编码实现 → 测试验证 → 部署上线
```

**格式要求**：
- 使用 `→` 或 `->` 作为箭头
- 步骤间用空格分隔
- 每个步骤简洁明了
- 总长度建议不超过一行

### 2. 表格形式（多步骤流程）

**适用场景**：
- 步骤较多（5-15 步）
- 需要详细说明每个步骤
- 包含输入输出信息

**示例**：

| 步骤 | 操作 | 输入 | 输出 | 负责人 |
|------|------|------|------|--------|
| 1 | 需求收集 | 用户需求 | 需求文档 | 产品经理 |
| 2 | 需求分析 | 需求文档 | 需求规格 | 分析师 |
| 3 | 系统设计 | 需求规格 | 设计文档 | 架构师 |
| 4 | 开发实现 | 设计文档 | 源代码 | 开发工程师 |
| 5 | 测试验证 | 源代码 | 测试报告 | 测试工程师 |

**格式要求**：
- 使用标准 Markdown 表格
- 包含步骤编号
- 明确输入输出
- 可选：负责人、时间等

### 3. Mermaid 图表（复杂流程）

**适用场景**：
- 有分支判断
- 包含循环结构
- 有跳转或回退
- 多个并行路径
- 时间维度的规划视图（Timeline）与用户体验旅程（Journey）

#### 3.1 状态流转图

> **定位**：本小节只示范 `stateDiagram-v2` 的**语法与适用情形**，**不在此复述本规范的状态机**。本包内所有状态集合、流转与版本号递增时机由 [status-definitions.md](../../references/status-definitions.md#状态流转规则) 单点承载；若本示例与该文件不一致，视为规范缺陷，当轮修正。

下例为**与本项目无关的中性语法示意**（故意不使用 `初稿/正式/草案/废弃` 等规范状态值，以免形成第二套表述）：

```mermaid
stateDiagram-v2
    [*] --> 新建
    新建 --> 评审中 : 提交评审
    评审中 --> 新建 : 评审不通过
    评审中 --> 已发布 : 评审通过
    已发布 --> 已下线 : 废止
    已下线 --> [*]
```

#### 3.2 流程图

```mermaid
flowchart TD
    A[开始] --> B{条件判断}
    B -->|是| C[执行操作A]
    B -->|否| D[执行操作B]
    C --> E[结果处理]
    D --> E
    E --> F{检查结果}
    F -->|通过| G[结束]
    F -->|失败| H[错误处理]
    H --> B
```

#### 3.3 时序图

```mermaid
sequenceDiagram
    participant 用户
    participant 前端
    participant 后端
    participant 数据库
    
    用户->>前端: 发起请求
    前端->>后端: API调用
    后端->>数据库: 查询数据
    数据库-->>后端: 返回结果
    后端-->>前端: 响应数据
    前端-->>用户: 显示结果
```

#### 3.4 类图

```mermaid
classDiagram
    class 用户 {
        +用户ID: String
        +用户名: String
        +登录()
        +注销()
    }
    
    class 订单 {
        +订单ID: String
        +金额: Decimal
        +创建订单()
        +取消订单()
    }
    
    用户 "1" --> "*" 订单 : 下单
```

#### 3.5 时间线图（Timeline）

**适用场景**：按时间阶段展示演进与分组（典型：产品路线图、版本演进概览）。

```mermaid
timeline
    title 产品演进时间线
    section 近期
        2026 Q1 : 实时会话 : 多端同步
    section 中期
        2026 Q3 : 离线可用
    section 远期
        2027 : 开放集成
```

**格式要求**：
- 顶层必须包含 `title`；用 `section` 分组，叶子节点为「时间视野 : 条目1 : 条目2」
- 时间粒度在同一图内保持一致（全为季度或全为年度）
- 条目名称用产品能力/主题，不写任务或里程碑（执行信息不入设计文档）

#### 3.6 用户旅程图（Journey）

**适用场景**：从用户视角展示体验与价值变化（典型：用户价值演进、场景体验概览）。

```mermaid
journey
    title 新用户首次体验旅程
    section 注册
      下载与打开: 4: 新用户
      手机号验证: 3: 新用户
    section 首次会话
      找到联系人: 2: 新用户
      发出第一条消息: 3: 新用户
```

**格式要求**：
- 行格式固定为 `活动名: 分数: 角色[, 角色…]`，分数取 **1-5** 整数
- 角色名与文档中 `STK`/`UC` 使用的角色称谓一致，不自造新词
- 若同一图内对比当前与目标，在活动名前标「当前/目标」（如 `当前-找到联系人: 2: 新用户`）

## 格式选择决策树

> 下列决策树适用于**流程/逻辑类**表达；Timeline 与 Journey 属于规划/体验类视图，直接按 3.5 / 3.6 选用。

```mermaid
flowchart TD
    A[开始分析流程] --> B{是否线性流程?}
    B -->|是| C{步骤数量 ≤ 5?}
    B -->|否| H[使用 Mermaid 图表]
    C -->|是| D[使用简化箭头]
    C -->|否| E{需要详细说明?}
    E -->|是| F[使用表格形式]
    E -->|否| G[使用简化箭头分行]
    
    style D fill:#e1f5fe
    style F fill:#f3e5f5
    style H fill:#e8f5e8
```

## 常见错误示例

### ❌ 错误的复杂流程使用箭头

```
用户登录 → {验证成功?} → 成功 → 进入系统
              ↓
            失败 → 重新登录
```

**问题**：包含分支判断，不应使用简化箭头

**正确做法**：使用 Mermaid 流程图

### ❌ 错误的简单流程使用 Mermaid

```mermaid
flowchart LR
    A[步骤1] --> B[步骤2] --> C[步骤3]
```

**问题**：简单线性流程，过度复杂化

**正确做法**：使用简化箭头 `步骤1 → 步骤2 → 步骤3`

## 最佳实践

1. **优先选择最简单的格式**：能用箭头就不用表格，能用表格就不用 Mermaid
2. **保持一致性**：同一文档中相同类型的流程使用相同格式
3. **考虑读者**：技术文档可用 Mermaid，业务文档可用表格
4. **工具兼容**：确保目标环境支持所选格式
5. **可维护性**：选择易于更新和维护的格式

## 工具支持

### Mermaid 编辑器
- **在线**：https://mermaid.live/
- **VS Code**：Mermaid Preview 插件
- **Typora**：内置 Mermaid 支持
- **GitLab/GitHub**：原生支持 Mermaid 渲染

### 表格工具
- **Markdown**：标准表格语法
- **Excel/Google Sheets**：可导入导出
- **在线表格生成器**：支持 Markdown 格式

### 箭头符号
- **标准箭头**：`→` (推荐)
- **简单箭头**：`->` (可接受)
- **长箭头**：`==>` (特殊用途)
- **双向箭头**：`<->` (双向关系)
