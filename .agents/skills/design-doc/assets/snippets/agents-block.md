## 设计优先（design-doc）

本项目采用 design-doc 管理产品设计，设计目录为 `ued/`（尚未创建时同样适用）。技能入口：`.agents/skills/design-doc/SKILL.md`。

1. **先设计，后实现。** 增加或修改功能、修复缺陷、改变产品可观察行为，或修改设计文档时，必须先调用 design-doc 技能，完成 `.agents/skills/design-doc/references/workflows/before-code-change.md` 定义的编码前 Gate。Gate 必须早于任何编辑，不得事后补写或跳过。
2. **设计是实现依据。** 只依据已纳入当前产品基线、revision 对齐的正式设计实现。设计缺失或有误时，先完善设计并经用户确认，再实施代码。
3. **设计变更走流程。** 正式设计的修改、解冻、状态与基线变更，按 design-doc 工作流执行，不得自行绕过。
4. **实现不超出设计。** 实现中发现设计未覆盖的行为、接口、数据结构或约束时，暂停实现并回到设计审查。
5. **实现后验证一致性。** 对照设计检查实现结果；修改设计文档后运行 `check_docs.py`。测试通过不代替设计一致性检查。
6. **设计目录只放设计。** `ued/` 仅存放设计文档，不存放可执行实现代码（算法、契约、状态机等设计描述除外）。
